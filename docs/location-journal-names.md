# 位置画面と日誌の位置名

経路・移動履歴を開く間は、同じメニュー内の家族一覧（名前・位置・更新時刻）と全体状況を畳みます。経路・移動履歴を閉じると戻ります。自動更新で一覧を再描画しても開閉状態は維持します。

日誌は、自宅・職場などの既存の標準名を残し、それ以外は取得済みの住所・地名を優先して保存・表示します。拠点の登録名は滞在判定用に保持します。位置名の保存後は、その日の保存済み日誌も更新し、検索用の内容へ反映します。同じ名前の再保存では日誌の内容バージョンを増やしません。後から得た住所は、過去の選択日の表示にも反映します。

住所は従来どおりブラウザの Google Maps Geocoder で取得します。文字レポートからの取得に加え、保存済み日誌に「位置名を確認して保存」を追加しました。利用者の操作で、現在共有中の滞在記録を参照し、住所・地名を保存します。日誌側の新規取得は都道府県・市区町村・町丁目までの住所要素を使用し、番地や建物名を保存しません。1回の操作で参照する家族、新規住所取得、保存は各20件までです。

未取得の位置名をすべてバックグラウンドで自動解決する処理ではありません。地図の設定・位置共有・滞在地点が利用できない場合は未取得の記録が残ります。共有停止済みの過去の日誌は引き続き表示できますが、その家族の地点を新たに Google Maps へ送信しません。保存失敗を成功として表示しません。

滞在のアーカイブは代表地点を住所確認用に保存します。地点が NULL の場合は座標 0,0 へ変換しません。既存のアーカイブの座標を一括で書き換える処理やマイグレーションはありません。

検証は家族を分けた SQLite の住所保存・日誌更新・冪等性・共有停止・失効・CSRF、アーカイブ地点、合成DOMの位置名取得・保存失敗・番地除外、経路開閉の実ハンドラを対象にします。実際の利用者の GPS や本番日誌へのテスト書込みは行いません。
