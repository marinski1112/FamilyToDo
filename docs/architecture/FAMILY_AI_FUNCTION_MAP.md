# Family AI ownership map

Verified against main `a430721d4a7dbd79189ced2cc2aae6be03195449`.

This map separates the interactive Family AI domain from shared AI policy/privacy/diagnostic helpers and from product features that merely consume AI.

## Canonical boundaries

| Concern | Canonical owner / exported function | Route / caller | Data / side effects | Safety / regression boundary |
| --- | --- | --- | --- | --- |
| Interactive Family AI read/plan | `src/family-ai.ts#familyAiQuery()` (`familyAiPlan` is the same owner) | `POST /api/family-ai/query`, `POST /api/family-ai/plan` via `src/context-api-routes.ts`; browser flow in `public/assets/family-ai.js` | tokenizes same-family members/subjects, chooses deterministic or provider planning, executes allowlisted read tools, or returns a signed 10-minute confirmation plan for a write | authenticated OWNER/ADMIN; bounded question; forbidden intents rejected; tool args are validated; writes are not executed during planning |
| Confirmed Family AI write | `src/family-ai.ts#familyAiExecute()` | `POST /api/family-ai/execute` | verifies signed confirmation, claims `family_ai_action_receipts` idempotency nonce, performs the allowlisted mutation, records activity, and queues Calendar projection when applicable | authenticated OWNER/ADMIN + CSRF; family/member identity embedded in signed token must match; one nonce cannot execute twice |
| Provider selection | `src/family-ai.ts#familyAiProvider()` | Family AI planner/connection/model surfaces and consumers that explicitly reuse this policy | selects `GEMINI` or `WORKERS_AI` from deployment configuration; there is no implicit provider failover | provider choice is explicit; missing selected provider configuration fails closed rather than silently switching provider |

## Ownership rules

- `src/family-ai.ts` is not merely a Gemini helper. It is also the canonical interactive Family AI read/plan/confirmed-write business owner. Keep its confirmation-token, tenant and idempotency boundaries intact when extracting common provider code.
- `familyAiPlan` is an alias of `familyAiQuery`, not a second planner implementation. The browser intentionally plans first and calls `familyAiExecute()` only after explicit confirmation.
- Do not treat every Gemini consumer as owned by Family AI. Task rough input, Family Daily Journal AI, LINE digests and Google/Home adapters keep their own business/evidence/fallback semantics even when they reuse provider, profile or diagnostic helpers.
- Do not make `resolveAiModelInventory()` the runtime model selector for all AI features. Current source contains feature-specific model policies as well as the generic family-scoped Family AI resolver.
- Do not let AI consumers read raw personalization columns when `loadSafeFamilyAiProfileContext()` is the applicable boundary. Master opt-in plus field-level permission and minimization are part of the privacy contract.
- Do not store prompts, model response bodies, API keys, raw family content or raw sensitive profile fields in generation diagnostics. Diagnostics are classification/evidence metadata only.
- Provider configuration is explicit. A selected `GEMINI` or `WORKERS_AI` path must not silently fail over to the other provider without a separate product/security decision.
- Search returning zero is not evidence that an AI consumer, contract or adapter is absent. Only positively read source/contracts are classified here.
