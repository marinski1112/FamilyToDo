# Androidネイティブ版とWeb版の更新契約

Androidの画面はAPKに同梱する。WebのHTML/JS変更は既存APKに反映されない。サーバー側の保存先は同じD1、権限・完了条件・通知・カテゴリの業務ルールはWorkers APIを唯一の実装として両クライアントから呼ぶ。

- 画面操作が変わった場合はWeb画面とAndroid画面をそれぞれ更新する。APIや業務ルール変更時は両画面の回帰確認をする。
- Android専用の読み取り契約は `/api/android/v1/*`。既存v1の応答や意味を破壊せず、新しい項目は追加する。破壊的変更はv2を新設し、配布済みAPKの移行期間中はv1を維持する。
- 変更が必要なとき、サーバー公開前に対応APKをビルドして身内へ配る。古いAPKで誤保存する危険がある変更は、サーバー側で明確な更新要求エラーとして扱う。
- Androidは家族と本人の可視範囲で受け取ったデータのみ暗号化して端末に保存する。キャッシュは読み取り専用で、Webと同じ保存結果はサーバーAPIから再取得する。失効や家族切り替えの実機動作を確認するまでは本番運用しない。
- CIはWorkersの契約テストとAndroidのデバッグAPKビルドを確認する。ログイン、権限、通知、オフライン復帰、端末間同期、機能ごとの表示は実機E2Eが必要。

機能の進捗と残件は Issue #1144、作業中のドラフトは PR #1143 を参照する。
