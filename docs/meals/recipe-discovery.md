# 外部レシピ検索と自由入力の分量

ごはん→レシピ→「サイト全体から探す」で、家族に未登録の料理をクラシル・デリッシュキッチンの公開検索から探せます。サイトを選択し、キーワード送信を明示したボタンを押した時だけ、固定HTTPSの公開検索ページを1回取得します。料理名と正規化した同サイトのレシピURLを最大12件表示します。候補の材料・手順は取得せず、リンク選択→既存URL取り込み→出典と内容を確認→保存して初めて家族の献立候補になります。

これは外部サイトの全データを複製したDBや公開APIとの正式連携ではありません。検索順位・収録内容・取得可否はサイト側に依存し、先頭ページ以外の一括収集はしません。ログインや有料部分は取得を迂回しません。サイトの公開条件・HTML形式が変わった時や結果が空の時は、「サイトで探す」からURL取り込みへ進めます。AI献立の候補は従来どおり確認して保存した自家族レシピのみです。

検索は既存認証とCSRFで保護。家族ごとに新規検索20回/UTC日、1操作1回の外部通信、10秒/2MB上限、転送不許可です。HTML/画像/scriptは保存・実行しません。検索receiptには入力hash、状態、時刻、表示用料理名/URLのみを保存し、失敗結果も含め同じrequest_idの再送で再取得しません。7日以前のreceiptは新規検索時に自家族分を最大20件削除します。Cron、AI、追加API keyは使いません。MEALS_DBの0011 migrationは既存deploy手順で適用します。

分量欄は「通常入力」と「自由入力」を選べます。自由入力では「お好みで(1〜2つまみ)」「約半量、味を見て追加」など80文字以内の表記を保存できます。数値だけの入力は数値モードで扱い、空欄・制御文字・NaN/Infinityを拒否します。単位欄はテキストの時に隠れます。保存済みの表記は献立snapshot・料理・買い物確認でも維持し、人数換算・加算・在庫の消費を行いません。買い物への追加は未選択から利用者が選んだ時だけです。従来の数値レシピの構造・再送hashを変更しません。
