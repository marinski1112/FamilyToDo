# ホットクック公式レシピ

SHARP公式のホットクック詳細URLを「レシピ → URLから取り込む」に貼り付け、材料・手順を確認して保存する。取り込みは下書きであり、保存・献立反映は本人操作。「食べたいものにも追加する」の既存導線も利用できる。

「今週の5品を提案」の「登録済みのホットクック公式レシピを優先する」を選択すると、時間条件に合う登録済み公式URLの候補を優先する。5品以上なら公式候補だけ、5品未満なら全公式候補を含めて他の料理で補う。候補不足時は既存の繰返し表示を維持。AIが優先条件を破った場合もコードによる候補に戻す。通常の献立提案・外部検索の初期設定は維持する。

2.4Lという容量だけで機種互換性を推定しない。公式サイトで本人の型番を選び、その詳細URLを取り込む。URLの機種名とメニュー番号、人数の注記を手順に残す。所要時間は公式の調理時間であり、準備・放置時間を自動補完しない。

公開ページが利用する固定の公開JSONを、Cookieや認証情報を送らず1回取得する。HTTPS・正確なホスト・hotcook/機種/レシピ番号のパスだけを受け付け、JSONのappliance・modelsを照合する。転送や機種変更、多料理・材料グループなど未対応形式は手入力へ案内する。公開仕様変更で取得できなくなる可能性がある。サイト全体の複製、Sharpログイン、機器送信、画像・ダウンロード先の取得は行わない。

既存URL取り込みの10秒・2MB制限、家族×UTC日20新規ジョブ（失敗を含む）、同一request_idの再試行キャッシュを共有し、AIは取り込みに使用しない。数量の範囲・補足は自由分量のまま保持し、人数換算・在庫自動差引きに使用しない。通常の保存revision・同一URL重複防止・希望との紐付けも維持する。

公式サイト内のキーワード検索をアプリ内で自動取得する機能は未追加。公式サイトで探してURLを取り込む。Androidは既存のWeb取り込み・提案導線で利用し、ネイティブ画面への移植は別作業。

検証: 合成公開JSONで許可URL、機種不一致、文字分量、画像除外、転送・429・形式不良・サイズ上限、再試行、未保存、AIの優先違反、画面入力・確認保存を検証。実家族の認証画面・実機調理の検証は別途必要。
