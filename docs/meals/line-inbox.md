# LINE料理受信箱

Web MVP PRの上に積む拡張です。`MEALS_ENABLED=true` と `MEALS_DB` が有効な環境のみ動作します。専用DBへ `meals-migrations/0002_meal_line_inbox.sql` を適用します。既存DBのスキーマ追加はありません。

既存WebhookのHMAC検証後、LINEユーザーIDから既存DBのactiveメンバーを解決します。個別トークのテキストのみ対象です。グループ/ルーム、未連携・無効メンバーは料理受信箱へ書き込みません。家族IDをメッセージから採用しません。

- `ハンバーグ食べたい` / `食べたい: カレー`: Web受信箱へ。確認ボタンで食べたいものに追加。
- http/https URL、または `レシピ URL`: 出典候補として受信箱へ。Webで出典を確認し、材料と手順を手入力してレシピ登録。入力画面にはURLを引き継ぎます。登録後は受信箱で「確認済みにする」を押します。
- 未対応の文章・画像・動画は既存の処理を維持します。AI解釈、画像保存、URL取得、YouTube解析は含みません。

WebhookイベントID（欠落時はメッセージID）と家族IDのハッシュで重複排除します。元のLINE識別子は専用DBにコピーしません。同一内容の別イベントは別候補です。確認/破棄後も受信行を保持して再配信による復活を防ぎます。保存はreplyTokenや送信トークンの有無に依存しません。返信には料理名やURLを載せません。保存失敗時は503でLINEの再配信対象にします（LINE側の再配信設定に依存）。既存の返信失敗時の処理は維持します。

Web操作はログイン・CSRF・家族スコープを検証。食べたいものへの追加と受信確認は専用DBの同一batch transactionで行います。確認済みの食べたいものを削除した後も再実行で復活しません。

履歴は重複排除のため残します。自動削除は未実装です。画像等の機微なデータを扱う将来のInbox拡張時には保持期限と再配信用tombstoneの分離を追加してください。

確認: `npm run check:meals`（13件: SQLite統合12 + Web受信箱DOM1）、署名・家族分離・重複/削除後再送・保存障害・HTTPを呼ばないこと、既存Webhook/ログprivacy契約、typecheck、既存回帰。
