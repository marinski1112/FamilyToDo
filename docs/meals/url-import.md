# URLからレシピを取り込む

レシピ一覧の「URLから取り込む」、またはLINE受信箱の同名ボタンから開始します。取得はログイン利用者の明示操作時だけです。確認・編集画面には料理名、人数、所要時間、材料、手順、出典URLを引き継ぎます。保存ボタンまでは登録レシピ・献立・買い物を変更しません。人数・時間・材料の曖昧な数量は空欄で、元の材料表記と出典リンクを表示します。

## 対応と制限

- HTTPSの `cookpad.com/jp/recipes/<数字>`、`www.kurashiru.com/recipes/<UUID>` と `delishkitchen.tv/recipes/<数字>`（wwwも可）の公開ページ。追跡query/fragmentを除去します。
- JSON-LDの単一Recipe、配列、@graph、HowToSection/HowToStepに対応。複数Recipe、材料・手順を特定できないページは手入力へ。
- 材料の明確な末尾数値・単位、分数、大さじ/小さじを通常コードで抽出。「少々」「適量」などの明示された末尾表記は数量テキストとして保持します。「1,2本」のような曖昧な区切りや数量の範囲は元表記を残し、数値を空欄にします。換算、AI推測は採用しません。ISO時間は分へ換算します。
- YouTubeは別の動画取り込み処理に対応（[仕様](youtube.md)）。その他のサイト、ログインを要するページは手入力。サイト側の取得拒否や構造変更でも手入力が利用できます。
- AIへの送信・モデル呼出しはありません。AI抽出は後続の独立した拡張です。

## 取得と保存

許可ホストとパスを完全一致で検証し、IP/内部ホスト・認証情報・非標準port・HTTPを拒否します。redirectはmanualで最大3回、各転送先を同じ規則で再検証。Cookie/Authorization等を転送しません。10秒timeout、2MB（展開後のstreamも計数）、text/htmlだけ。画像・動画・外部JSON-LD・instructionリンクを取得せず、スクリプトも実行しません。

専用DBの0004に家族別のrequest receiptと確認用draftを保存。家族ID/作成者は認証context由来。CSRF検証後に一意なclaimを取得し、同じrequest_id/URLの再送は成功/失敗を再利用し、重複した取得をしません。同じIDでURL変更は拒否します。新規取り込みは家族/UTC日20回まで（失敗も含む）。Workerがclaim後に中断したRUNNINGは再取得せず手入力へ案内。履歴は当面保持し、raw HTML/画像/動画、promptやAI回答は保存・ログ出力しません。確認画面から既存save_recipeの入力検証・revision・tenantルールで保存します。LINE受信箱は登録後に利用者が「確認済みにする」を操作します。

## 検証

献立SQLite/API/DOMテスト、型・JS構文・静的参照を確認。URL拒否、転送先再検証、bytes/type制限、並行claim、成功/失敗再送、家族分離、利用上限、保存前の未変更、数量空欄、通信応答喪失からの再試行を含みます。公開デリッシュキッチン1ページのJSON-LD抽出を確認。ローカルChromiumのsyntheticデータで確認・空欄による保存拒否・補完後の保存、320/390/768pxのoverflowなしを確認。本番での家族ログイン操作は利用者確認待ちです。

### ホットクックの材料グループ・時間・補足

公式データの単一英字の材料グループ（A・B等）は材料名に混ぜず、確認用の手順欄に所属材料を残す。数量をグループ間で合算しない。時間は分・時間・時間と分（例: 1時間25分＝85分）に対応し、曖昧な表記は手入力のままにする。公式の text.BK / text.BT とその後の説明は「出典の補足」として手順の末尾に保持する。未知の構造・複数料理の自動統合はしない。失敗した取り込みIDは引き続き同じ結果を返すため、修正後はページを再読込して新しい取り込みを開始する。

### クックパッド

公開ページに埋め込まれたJSON-LDを利用します。人数・所要時間がない場合は空欄のまま確認画面へ渡します。`https://cookpad.com/jp/recipes/26622092` で料理名・材料5件・手順3件の抽出を確認。「ゴーヤ 1,2本」は数量を確定せず元表記を保持します。Cookpad形式のAPIテストとDOMテストで、未保存の下書き・未入力での保存拒否・補完後の保存を検証します。ログインが必要なページや取得を拒否されるページは手入力になります。
