# 確定した単位だけの換算

レシピと保存済み献立snapshotは入力した単位を維持し、必要量の合計・買い物の不足計算・料理完了時の在庫確認だけで、kg→g、L→ml、mL→mlを換算します。係数は通常コードの固定値1000/1です。材料名は完全一致を維持し、別名の推測、質量と体積の相互変換、パック/個/カップ/大さじ等の重量・体積換算は行いません。少々・適量・お好みでなどの自由入力は換算・加算・在庫差し引きの対象外です。

在庫はEXACT、購入日到来、期限内の購入分だけを使用。kg/g、L/ml/mLを同じ基準単位にして不足分を表示し、利用者が買い物へ追加する品目を選びます。料理の確認では基準単位での必要量と、元の購入分の登録単位で実際に減らす量を両方表示します。例: 使用量600g、購入分0.6kg。保存は在庫lotの単位を変更せず、その単位で整数tickを減らします。FEFO・最大16購入分・確認hash・transaction・再送receiptは従来どおりです。

lotの精度は登録単位の0.0001です。換算後の必要量がlotの1tickに満たない場合は切り上げ消費しません。必要量を超えない整数tickだけを使い、端数は手動調整できます。人数換算と同名合算後に整数tickがJSの安全整数範囲を超える入力は拒否します。質量/体積を別々に保ち、密度や包装の大きさをAIに推測させません。

既に追加した週の買い物は書き換えず、同じ週を再追加できない元DBのreceiptを維持します。古い単位の確認画面や消費previewは現在の計算hashと異なれば再確認を要求し、保存済み料理完了receiptの再送は再消費しません。migrationやCronの追加はありません。
