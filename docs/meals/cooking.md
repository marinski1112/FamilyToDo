# Cooking画面の手順再開・タイマー

「料理をはじめる」で、選択した日の保存済み献立スナップショットを開く。材料と人数は従来通り、その日に保存された料理・数量を使用する。前へ/次へで手順を切り替え、その位置をこのブラウザのlocalStorageへ保存する。

タイマーは1〜180分を自分で指定。開始、一時停止、再開、解除に対応する。計測は終了時刻のタイムスタンプから残り時間を計算し、setIntervalの回数は累積しない。画面が遅延したり再読み込みされた場合も、その時点の時刻で再計算する。一時停止時は残りミリ秒を保存する。計測中・一時停止中のタイマーを入れ替える場合は確認する。

保存キーは献立のランダムなリビジョンと日付で区別する。別の日・別リビジョン・別家族の新しい献立へ以前の状態を流用しない。保存内容は手順番号、終了時刻、一時停止の残時間、更新時刻だけで、料理名、材料、氏名、トークン等は含めない。7日以上古い状態や不正な型/範囲は読み込まず、保持する料理状態は最大20件。アプリの他のlocalStorageキーは削除しない。

localStorageが使えない場合も手順・タイマー操作をメモリ内で続けられる。画面に再開位置の保存が使えない旨を表示する。料理画面を離れると定期更新を解除する。バックフォワードキャッシュから戻った場合は献立をAPIから読み直す。画面が再表示された場合は終了時刻から即座に残り時間を再計算する。タイマー操作はAPI書き込み・AI生成・在庫消費を行わず、料理完了は従来の確認付き「作った！」操作で行う。

このタイマーは時間経過の目安であり、食品の加熱・衛生・安全の確認を代行しない。終了時は画面に表示する。音・バックグラウンド通知・画面の自動維持・端末をまたぐ共有は未対応。閉じたブラウザが自動で通知するという表示はしない。料理画面のLive音声対話・代用品質問は別工程。

検査：計測遅延・再読み込み・一時停止/再開・期限切れ/不正データ・保存拒否・最大20件・異なる献立の分離・料理UIの明示操作とサーバー書込なしを合成検査。Chromiumの320/390/768幅で手順再開、タイマー再開、期限到達、解除を確認。
