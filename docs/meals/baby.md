# 離乳食の条件と調理前チェック

Webの「ごはん → 離乳食」から、家族ログにある有効なBABY/CHILD対象を選択する。名前・生年月日は元DBのfamily_log_subjects（連携メンバー名はmembers）を参照し、MEALS_DBには複製しない。月齢は家族のタイムゾーンの当日と暦月で計算する。未設定・不正・未来の生年月日は未確認扱い。

MEALS_DBのmeal_baby_profilesには対象ID、現在の段階、離乳開始準備を確認したか、導入済み食材、避ける食材だけを保存する。家族内で共有する条件であり、プロフィールそのものをAIへ送信しない。保存はリビジョン付きの単一SQLによる条件付き更新。同一内容の再送は再保存しない。別家族・非表示対象・無効メンバーに連携した対象は操作不可。

登録済みの自家族レシピから、材料名と調理前の保護者の確認を検査する。生年月日、条件、レシピをサーバーで読み直す。クライアントの食材・月齢は採用しない。条件・レシピの古いリビジョンを拒否する。チェックは読取のみ、献立・買い物・在庫・食事ログには書き込まない。

ルール `baby-checklist-1`：

- 12か月未満または月齢未確認では、明示されたはちみつ、または限定的な材料名検知によるはちみつがあるとBLOCKED。加熱済み・原材料確認済みの入力でもこの警告を解除しない。
- 登録した避ける食材と材料名が大文字小文字を無視した部分一致の場合BLOCKED。これは保守的な照合で、誤検知もあり得る。
- 未登録食材、未確認の段階・開始準備・はちみつ含有・加熱・形状や硬さ・全原材料とアレルゲンには個別の確認事項を表示。
- 全確認欄を完了してもREVIEW_REQUIRED。食品適性、全アレルゲン、量、栄養、窒息・食中毒リスクを網羅的に判定しない。「安全」「食べてよい」という結果は返さない。
- 入力変更時は表示済みの結果を消し、通信中の変更後に古い結果を表示しない。条件の未保存編集があれば保存を先に要求する。

材料名照合は表記違い・複合材料・加工品の原材料・混入を検出しきれない。導入済みの登録は医学的な安全認証ではない。段階や月齢から自動的に食べられる食品や硬さを推定しない。大人用レシピの自動転用・分量換算や、AIによる可否判定は行わない。明示的な同意と操作後、MEAL_BABY_GUIDANCEで未確認項目のコードのみを送り、最大3種類の優先確認項目を整理する。名前、生年月日、月齢、段階、導入済み・回避食材、材料名、調理確認の値は送らない。AIの自由文は表示せず、返された許可済みコードに対応する固定注意文を表示する。全項目と最終確認は常に残す。BLOCKEDではAIを呼ばない。モデル代替なし、1操作1回、家族UTC日10回まで（失敗含む）。同一ID/条件/メンバーの並行・再送は同じレシートを使い、失敗時も再呼出ししない。入力変更時の古い表示を抑止する。

## 通信失敗の分類

接続診断の安全な実行状態では、タイムアウト、通信失敗、認証・権限の拒否、APIの一時障害、応答形式の不一致を固定コードで区別する。例外の文章、Googleの応答本文、トークンは記録・表示しない。失敗結果の再送は既存の実行記録を再利用し、自動再試行や別モデルへの切替は行わない。

Google APIへの単一リクエストの待ち時間は最大30秒。回数上限・失敗キャッシュは維持し、待ち時間を延ばしても再試行や別モデルへの切替を増やさない。Liveの新規接続用トークン期限は従来どおり1分で、発行後に残り時間がない場合は開始しない。
