# 公開YouTube動画からのレシピ候補

ごはん→レシピ→URLから取り込む、またはLINE受信箱のレシピURLから開始する。公開YouTubeのwatch、youtu.be、shorts、embedを正規化し、固定の `https://www.youtube.com/watch?v=<11文字ID>` のみGeminiへ送る。開始・終了を秒で指定、1区間1〜600秒、終了24時間以内。初期値は0〜600秒。URLの共有用クエリー、再生リスト、認証情報、タイムスタンプ等は送らない。解析前に送信確認チェックを必須とする。リンク先を開いてから出典を確認できる手入力も残す。

サーバーはYouTubeへfetchしない。スクレイピング、字幕の取得、動画ダウンロード、R2保存、YouTube OAuthは行わない。GeminiのgenerateContentにfileData.fileUriとvideoMetadata.startOffset/endOffset/fps:1を渡す。Google側が区間指定を適切に処理することに依存し、対応モデル・無料枠・実プロジェクトでの利用可否は実際の呼び出しによる確認が必要。

MEAL_RECIPE_EXTRACT（OWNER/MEMBER）の既存モデル設定を使用。既定は3.5 Flash Lite→3.5 Flash。プロジェクト×モデル、家族×機能の既存AI予約を送信前に行う。最大2試行、5xxまたは不正な抽出・LOW確信度に限って次モデルへ進む。429・その他4xx・通信例外は再送しない。promptFeedbackのブロック、SAFETY/RECITATION等の明示的な拒否・未知の終了理由は次モデルへ送らず、候補を採用しない。MAX_TOKENSの未完了回答も採用せず、許可された2試行以内でのみ次モデルへ進む。LOW候補が得られていれば、後続失敗時もLOW候補を確認用として返せる。429は既存のプロジェクト回路停止を行い、別モデルで回避しない。

生成待ちの期限はMEAL_RECIPE_EXTRACTのみ30秒。既存機能とモデル一覧は10秒を維持。診断の合成検査以外で勝手に生成を試さない。結果や受付を失った場合は同一request_idで再試行できる。RUNNINGのジョブは再生成せず処理中として返し、別IDの手入力へ進める。HTML取り込みと共通のmeal_url_importsで、家族×UTC日20新規ジョブ（失敗を含む）まで。

抽出結果は料理名、人数、調理時間、最大50材料と50手順、HIGH/MEDIUM/LOWのみ厳格な型で検査する。数量は明示された数値のみ、不明はnullと空単位。人数・調理時間も不明ならnull。動画時間を調理時間にしない。手順は短い要約で、全文字幕や区間外の内容の補完は求めない。動画・音声・字幕の指示文は信頼せず、実行するツール・外部リンク・書込アクションは与えない。出典URL・モデル・日時・区間は通常コードが付与し、モデルに指定させない。

候補は未保存。人数、時間、食材数量・単位を自分で補い、手順と抜けを出典で照合した後に通常のレシピ保存を行う。AIの確信度は正確性の保証でも、離乳食・アレルギー・衛生等の安全判定でもない。料理手順・材料そのものの抽出誤りをスキーマだけで排除することはできない。全動画を自動解析する機能ではなく、指定区間外の手順・材料は欠け得る。

保存時は家族内のREADY抽出ジョブを参照し、URLが一致する場合にrecipe_sourcesへ出典履歴を残す。レシピ保存と出典履歴は同じMEALS_DBのbatchで原子的に確定する。古い編集は出典履歴も更新しない。再送で履歴を増やさない。ユーザーが出典URLを変更した場合は元の抽出履歴を新URLへ付けず、手入力レシピとして保存する。後から出典URLが変わったレシピでは旧URLの抽出メタデータを表示しない。

保存するのは正規化した候補とエラーコード、出典メタデータだけ。動画bytes、字幕全文、プロンプト、未検証のAI生レスポンス、APIキー、家族プロフィールは保存・ログしない。候補内の料理テキストはAI生成のため、文字単位の全文字幕除外までは保証しない。画面はすべてエスケープして表示する。

Googleの公式案内ではYouTube URLはプレビューで公開動画のみ（非公開・限定公開不可）。価格・レート制限は変更され得る。FamilyToDoから無料利用を保証しない。実動画の精度と既存APIキーのモデル対応は未検証。ローカル・CI検査とブラウザQAは合成レスポンスで行い、実AI生成はしない。
