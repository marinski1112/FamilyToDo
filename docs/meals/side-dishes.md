# 副菜の提案と保存

今週の献立で平日の主菜を選び、「リストにない副菜を提案」を開きます。クラシル/DELISHの公開検索語（既定「簡単 副菜」）・時間を選び、未登録の実在レシピ最大6件からAIに5品を選ばせます。希望リストへの事前登録は不要です。主菜の料理名もAIへ送ることを画面で説明します。別家族/未登録/週外の主菜は拒否。AIの料理ID以外の出力、不正出力や拒否は採用しません。検索/取り込み/提案の既存上限と再送receiptを共有し、追加の無制限生成は行いません。

各副菜を出典と照合してレシピ保存した後、主菜がある平日に1品ずつ追加できます。主菜・人数・週末と未保存の編集を保持します。適用後も副菜を選び直す/副菜なしにできます。レシピを保存するだけでは献立を変更せず、後続の下書き保存/献立確定で更新します。既存の副菜を入れ替える場合も確認画面から明示的に反映します。

献立itemに任意のsides snapshotを保存し、主菜のrecipeフィールドは維持します。副菜のない既存献立のJSON/hashを変えません。1日1副菜、主菜と同一ID不可。保存は自家族のactiveレシピだけを解決し、人数と各レシピの元人数から通常コードで必要量を計算します。材料は買い物不足量/FEFO在庫消費へ合算します。少々等は換算/在庫減算せず、料理画面は主菜・副菜別の材料と手順を表示。「作った！」は献立revisionで両料理を1回だけ記録/消費します。レシピ編集後も既存献立のsnapshotは変わりません。新migration/Cronなし。

検証: check:meals 93件、型/JS構文/静的参照成功。家族分離、過剰/同一副菜拒否、独立人数換算、買い物/FEFOの700g合算と二重消費防止、snapshot維持、主菜/人数/週末維持、提案前保存なし、再送の通信上限をSQLite/API/DOMで確認。Chromium合成データで検索1回/6取得/AI1回→副菜5品の個別確認→主菜/人数/週末を保った下書き保存、320/390/768px overflow/page errorなし。実Gemini/本番ログイン後の操作は未検証です。
