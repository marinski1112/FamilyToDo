# UI改善と判断待ち（2026-10-06）

## 今回の修正

- 暗色のチェックボックス: 旧チェックリストの白背景と通常フォームのネイティブ表示を統一。未選択・選択・部分選択・フォーカス・無効を区別する。スイッチとhidden入力は対象外。
- 地図: 最終測位からの経過やブラウザ/localStorageの時刻で滞在時間を作らない。古い位置は「最終確認：滞在」または「位置情報待ち」。測位があるだけの状態も移動と断定しない。名前ではなくmemberIdでマーカーと行を対応付ける。サーバーの履歴・測位・共有設定は変更しない。
- レシピ: 登録・編集・URL取り込み確認の共通フォームに「食べたいものにも追加する」（初期OFF）。レシピ・出典・希望は同じD1 batchで保存。保存内容が一致しない競合では希望を追加しない。同じレシピIDの再試行は重複しない。既存の同名の別希望には干渉しない。
- 希望の名前は追加時のスナップショット。後のレシピ編集では既存希望の名前を書き換えない。希望を削除した後、改めてチェックして保存すれば再追加できる。

## 確認が必要な改善案

|改善案|判断が必要な内容|
|---|---|
|履歴に基づく滞在時間|測位間隔が空いたら「不明」とする上限、精度が低い測位の扱い、自宅/登録地点の範囲。離れた後の最終測位だけで滞在を延ばさないことを前提に設計する。|
|食べたいものとレシピの継続連携|追加後も料理名を同期するか、独立した希望のままにするか。同名のLINE希望と自動統合してよいか。現状は独立させる。|
|Androidで同時追加|ネイティブにも同じチェック欄を追加するか。現状は既存APIの互換性を保ち、Webフォームに追加。Android全体PRは引き続きドラフト。|
|LINE標準応答の整理|料理受信箱の返信と標準の問い合わせ不可返信が重なる。公式アカウント管理画面の標準応答をOFF/変更するかは本人判断。アプリの返信だけにすれば受信結果が分かりやすい。|

## 検証の区別

暗色の問題は実ログイン画面で確認した。全ページの状態は `ui-authenticated-qa.md` が正本。合成テストでは古い位置・同名メンバー・測位なし・共有OFF・連続表示、レシピ同時保存・家族分離・競合・再送・DB失敗時のrollback・応答消失時の入力保持を確認する。

実機の測位誤差、長時間の位置共有、Galaxy A21の表示とIME、Android実認証、実データでの同時保存は、この合成テストの成功だけで完了としない。家族の位置、名前、画像、Cookieは記録しない。
